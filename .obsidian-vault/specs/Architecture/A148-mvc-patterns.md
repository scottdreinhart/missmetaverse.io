# MVC Pattern Patterns

## Definition

MVC Pattern Patterns are **design patterns for working with MVC architecture**.

> "MVC separates application into three components: Model (data), View (UI), and Controller (input handling)." — Wikipedia

## Problem Addressed

Without MVC pattern patterns:
- **Complexity**: Code is complex and hard to understand
- **Coupling**: Components are tightly coupled
- **Testing**: Hard to test components
- **Maintenance**: Hard to maintain code

## Scope and Boundaries

- MVC Pattern Patterns ≠ MVC (MVC pattern patterns are patterns, MVC is an architecture pattern)
- MVC Pattern Patterns ≠ MVP (MVC pattern patterns are patterns, MVP is an architecture pattern)
- MVC Pattern Patterns is a **patterns**, not an architecture pattern

## When to Apply

- When building applications
- when separation of concerns matters
- when testing is important
- when maintenance is important

## Tradeoffs and When to Avoid

| Cost | Description |
|------|-------------|
| **Complexity** — MVC pattern patterns are complex |
| **Time** — MVC pattern patterns take time |
| **Over-MVC** — Don't use MVC for everything |

## Common Misuses

- **Everything MVC**: Not everything needs MVC pattern patterns
- **Confusing with MVP**: MVC pattern patterns ≠ MVP
- **Over-MVC**: Too many MVC components create complexity
