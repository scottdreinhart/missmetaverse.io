# Accessibility (A11Y) Pattern Patterns

## Definition

Accessibility (A11Y) Pattern Patterns are **design patterns for working with accessibility architecture**.

> "Web accessibility ensures that websites and web applications are usable by everyone, including people with disabilities." — W3C

## Problem Addressed

Without accessibility pattern patterns:
- **Exclusion**: Users with disabilities are excluded
- **Compliance**: Legal compliance requirements aren't met
- **Testing**: Hard to test accessibility
- **Maintenance**: Hard to maintain accessibility

## Scope and Boundaries

- Accessibility (A11Y) Pattern Patterns ≠ Accessibility (accessibility pattern patterns are patterns, accessibility is a frontend pattern)
- Accessibility (A11Y) Pattern Patterns = Semantic Versioning (accessibility pattern patterns are patterns, semantic versioning is a quality pattern)
- Accessibility (A11Y) Pattern Patterns is a **patterns**, not a frontend pattern

## When to Apply

- When building applications
- when accessibility matters
- when testing is important
- when maintenance is important

## Tradeoffs and When to Avoid

| Cost | Description |
|------|-------------|
| **Complexity** — Accessibility pattern patterns are complex |
| **Time** — Accessibility pattern patterns take time |
| **Over-accessibility** — Don't use accessibility for everything |

## Common Misuses

- **Everything accessibility**: Not everything needs accessibility pattern patterns
- **Confusing with semantic versioning**: Accessibility pattern patterns ≠ semantic versioning
- **Over-accessibility**: Too much accessibility creates complexity
