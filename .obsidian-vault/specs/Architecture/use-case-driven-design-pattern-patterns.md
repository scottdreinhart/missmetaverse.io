# Use Case Driven Design Pattern Patterns

## Definition

Use Case Driven Design Pattern Patterns are **design patterns for working with use case driven design architecture**.

> "Use case driven design organizes development around use cases that describe how users interact with the system." — Alistair Cockburn

## Problem Addressed

Without use case driven design pattern patterns:
- **Complexity**: Requirements are complex and hard to maintain
- **Alignment**: Development is misaligned with user needs
- **Testing**: Hard to test user interactions
- **Maintenance**: Hard to maintain user interactions

## Scope and Boundaries

- Use Case Driven Design Pattern Patterns ≠ Use Case Driven Design (use case driven design pattern patterns are patterns, use case driven design is an architectural pattern)
- Use Case Driven Design Pattern Patterns = Composition Root (use case driven design pattern patterns are patterns, composition root is an architectural pattern)
- Use Case Driven Design Pattern Patterns is a **patterns**, not an architectural pattern

## When to Apply

- When building applications
- when user needs matter
- when testing is important
- when maintenance is important

## Tradeoffs and When to Avoid

| Cost | Description |
|------|-------------|
| **Complexity** — Use case driven design pattern patterns are complex |
| **Time** — Use case driven design pattern patterns take time |
| **Over-use-case-driven-design** — Don't use use case driven design for everything |

## Common Misuses

- **Everything use case driven design**: Not everything needs use case driven design pattern patterns
- **Confusing with composition root**: Use case driven design pattern patterns ≠ composition root
- **Over-use-case-driven-design**: Too many use cases create complexity
