# Factory Method Pattern Patterns

## Definition

Factory Method Pattern Patterns are **design patterns for working with factory method architecture**.

> "The Factory Method pattern defines an interface for creating objects, but lets subclasses alter the type of objects that will be created." — GoF

## Problem Addressed

Without factory method pattern patterns:
- **Complexity**: Object creation is complex and hard to maintain
- **Coupling**: Code is coupled to specific classes
- **Testing**: Hard to test object creation
- **Maintenance**: Hard to maintain object creation

## Scope and Boundaries

- Factory Method Pattern Patterns ≠ Factory Method (factory method pattern patterns are patterns, factory method is a design patterns overview pattern)
- Factory Method Pattern Patterns = Design Patterns Overview (factory method pattern patterns are patterns, design patterns overview is a design patterns overview pattern)
- Factory Method Pattern Patterns is a **patterns**, not a design patterns overview pattern

## When to Apply

- When building applications
- when object creation matters
- when testing is important
- when maintenance is important

## Tradeoffs and When to Avoid

| Cost | Description |
|------|-------------|
| **Complexity** — Factory method pattern patterns are complex |
| **Time** — Factory method pattern patterns take time |
| **Over-factory-method** — Don't use factory method for everything |

## Common Misuses

- **Everything factory method**: Not everything needs factory method pattern patterns
- **Confusing with design patterns overview**: Factory method pattern patterns ≠ design patterns overview
- **Over-factory-method**: Too many factory methods create complexity
